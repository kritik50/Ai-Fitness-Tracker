FitTrack — AI-Powered Fitness Tracker
A full-stack fitness tracking app with an AI health coach built in. Log meals, track workouts, snap a photo of your food to auto-detect calories, and get personalized insights generated by Gemini — all in one place.

Live demo: https://ai-fitness-trackers.vercel.app/

What it does
Food Log

Log meals by breakfast, lunch, dinner, or snack
Type a food name and the calorie count gets estimated automatically using Gemini (you can still edit it manually)
Take a photo of your food — the app will identify what it is and log the calories for you
Delete individual entries, see today's total at a glance
Activity Log

Quick-add common workouts (running, cycling, yoga, etc.) with one click
Log custom activities with duration and calories burned
Calorie burn auto-calculates based on the activity type and duration you enter
Dashboard

Daily calorie intake vs. your personal limit with a progress bar
Calories burned vs. your daily burn goal
Active minutes and workout count for the day
BMI calculated from your height and weight
Weekly calories vs. activity chart (Recharts)
AI coach section — pulls 3 personalized health tips based on your actual logs
Profile

Edit your age, weight, height, and fitness goal at any time
Dark/light mode toggle that persists across sessions
Onboarding

3-step flow after signup to collect age, measurements, and goal
Sets personalized daily calorie and burn targets based on your goal (lose / maintain / gain)

Running locally
You need Node.js 20+ and npm.

1. Clone the repo

bash

git clone https://github.com/kritik50/Ai-Fitness-Tracker.git
cd Ai-Fitness-Tracker
2. Start the backend

bash

cd server
cp .env.example .env
# Fill in your values in .env (see Environment Variables section below)
npm install
npm run dev
The Strapi admin panel will be at http://localhost:1337/admin. Create your admin account on first run.

3. Start the frontend

Open a new terminal:

bash

cd client
cp .env.example .env
# VITE_STRAPI_API_URL=http://localhost:1337 (already set in the example)
npm install
npm run dev
App opens at http://localhost:5173.

Deploying to production
The recommended setup is Vercel for the frontend and Render for the backend with a PostgreSQL database.

Backend on Render
Create a Web Service pointing to the server directory.

Build command: npm install && npm run build
Start command: npm run start
Set these environment variables in Render's dashboard:

env

NODE_ENV=production
HOST=0.0.0.0
PORT=10000
CLIENT_URL=https://your-app.vercel.app
CORS_ORIGINS=https://your-app.vercel.app
DATABASE_CLIENT=postgres
DATABASE_URL=<render-postgres-connection-string>
APP_KEYS=<secrets>
API_TOKEN_SALT=<secret>
ADMIN_JWT_SECRET=<secret>
TRANSFER_TOKEN_SALT=<secret>
JWT_SECRET=<secret>
ENCRYPTION_KEY=<secret>
GEMINI_API_KEY=<your-key>
After the backend is live, open /admin, create your Strapi admin account, and the bootstrap script will automatically set the correct permissions for all API routes.

Frontend on Vercel
Create a project pointing to the client directory.

Framework preset: Vite
Build command: npm run build
Output directory: dist
Add this environment variable in Vercel's dashboard (not in .env):

env

VITE_STRAPI_API_URL=https://your-backend.onrender.com
Redeploy after saving — the URL gets baked into the build at compile time.

Note on free tier: Render's free web services spin down after 15 minutes of inactivity. The first request after sleep can take 10–15 seconds to respond. This is normal. Render's free PostgreSQL databases also expire after 90 days — consider Neon or Supabase as a free persistent alternative.

    │   │   ├── ai-coach/        # /insight — Gemini health tips
    │   │   ├── image-analysis/  # /analyze — food photo → name + calories
    │   │   └── profile/         # /me — update user profile
    │   └── index.ts             # Bootstrap: auto-sets API permissions on startup
    └── config/

Notes
The Vite dev server proxies /api/* to localhost:1337 so you never deal with CORS locally.
In production, all API calls go directly from the browser to the Render backend — make sure CORS_ORIGINS in your Render env matches your Vercel URL exactly.
Strapi permissions are set automatically at startup via the bootstrap function in server/src/index.ts — no manual permission configuration needed after deploy.
